# 核心铁律与避坑

## 适用范围
适用于安全边界、性能红线、数据可靠性、依赖控制和第一版范围控制。

## 规则条目

### R1: 渲染进程不得获得 Node.js 能力
**断言**：创建 `BrowserWindow` 时必须设置 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；渲染进程不得出现 `node:fs`、`electron`、`ipcRenderer` 直接导入。
**示例**：
```ts
const mainWindow = new BrowserWindow({
  webPreferences: {
    preload: preloadPath,
    nodeIntegration: false,
    contextIsolation: true,
    sandbox: true,
  },
});
```
**违规特征**：`webPreferences.nodeIntegration = true`，或 React 组件中写 `import { ipcRenderer } from "electron"`。

### R2: IPC channel 必须白名单化
**断言**：所有 IPC channel 必须集中声明在 `W:\提示词\electron\shared\ipcChannels.ts`；不得在组件中拼接字符串 channel。
**示例**：
```ts
export const ipcChannels = {
  libraryRead: "library:read",
  librarySave: "library:save",
  imageImportFromClipboard: "image:import-from-clipboard",
  archiveExportZip: "archive:export-zip",
  archiveImportZip: "archive:import-zip",
} as const;
```
**违规特征**：`ipcRenderer.invoke("image:" + action)` 或在多个文件中散落 `"library:save"` 字符串。

### R3: 第一版不得引入重型基础设施
**断言**：第一版 `package.json` 不得包含数据库、ORM、远程后端、登录鉴权或云存储 SDK；素材库只能使用本地 JSON 与图片目录。
**示例**：
```json
{
  "forbiddenV1Dependencies": [
    "prisma",
    "sqlite3",
    "better-sqlite3",
    "firebase",
    "@supabase/supabase-js",
    "next",
    "express"
  ]
}
```
**违规特征**：为本地素材管理引入 Prisma、SQLite、Supabase、Express、Next.js API Routes。

### R4: 导入图片必须复制到应用数据目录
**断言**：`library.json` 中只能保存应用数据目录内的 `imageFileName` 或相对路径；不得把用户原始外部路径作为唯一图片引用。
**示例**：
```json
{
  "id": "018f4cc0-4fd2-7a0e-8e7a-63b7f99f0b12",
  "imageFileName": "018f4cc0-4fd2-7a0e-8e7a-63b7f99f0b12.png",
  "prompt": "一只白色陶瓷杯，柔和自然光"
}
```
**违规特征**：只保存 `"imagePath": "C:\\Users\\Alice\\Desktop\\a.png"`，导致源文件移动后素材失效。

### R5: 写入 library.json 必须具备原子性
**断言**：主进程保存 `library.json` 时必须先写入临时文件，再重命名覆盖正式文件；不得直接覆盖正式 JSON。
**示例**：
```ts
await fs.writeFile(tempPath, JSON.stringify(library, null, 2), "utf8");
await fs.rename(tempPath, libraryPath);
```
**违规特征**：`await fs.writeFile(libraryPath, data)` 直接覆盖，且没有临时文件、备份或错误恢复策略。

### R6: 启动路径不得执行全量派生同步
**断言**：应用启动、首屏加载、`useLibraryStore.load()` 和 renderer ready 前后不得执行参数词库、分类词库、标签词库、图片缩略图、提示词解析、AI 分析等全量派生/同步任务；启动阶段只能读取必要的 `library.json`、视图设置和已保存缓存。全量词库重建、提示词扫描、批量图片处理必须由用户触发的数据变更流程执行，或放到可取消、分批让出主线程的后台任务中。
**示例**：
```ts
// 启动：只读取已保存词库，不全量重建。
const [libraryResult, viewSettingsResult] = await Promise.all([
  window.suyanApi.readLibrary(),
  window.suyanApi.readLibraryViewSettings(),
]);
set({ items: libraryResult.data.items, promptLexicons: viewSettingsResult.data.promptLexicons });
```
```ts
// 数据变更后才做同步。
await syncPromptLexiconsFromLibrary(set, get);
```
**违规特征**：启动后立即调用 `syncPromptLexiconsFromLibrary`、扫描全部提示词、合并全部词库、批量生成缩略图或在 renderer 主线程执行长循环，导致窗口已显示但点击、滚动、边栏无响应。

### R7: 性能问题必须保留可定位日志
**断言**：启动、首屏、慢 IPC、菜单切换、批量分析等曾出现卡顿的路径必须保留轻量性能日志，日志不得阻塞 UI，不得写入敏感提示词全文、API Key 或图片内容。新增重任务时必须能通过日志区分是主进程、IPC、renderer 首屏、页面切换还是后台任务耗时。
**示例**：
```ts
window.suyanApi.logStartupEvent("view-switch:committed", {
  durationMs,
  to: view,
});
```
**违规特征**：删除启动/慢操作日志后又新增重同步逻辑；出现“卡住”问题时只能凭主观猜测，无法从日志看到耗时阶段。

### R8: 词库清空与多工作区写入不得互相覆盖、不得回种默认
**断言**：分类 / 标签 / 参数三个词库工作区共享 `promptLexicons` 持久化对象时，每个工作区的自动保存**只能写入当前域**；其它域必须读取 store 中最新值，不得用挂载时冻结的 sibling draft 整包覆盖。`promptLexicons === null` 才表示“从未配置、可种默认”；用户清空后得到的空数组 / 空域**禁止**再经 `mergeMissing*Defaults`、`createDefaultPromptLexiconSettings` 或启动/导入同步静默回种。清空标签时必须同步清空 `tagOrder` 等关联索引。
**示例**：
```ts
// 自动保存：只写当前域。
const nextLexicons = {
  parameters: isParameterWorkspace ? normalizeParameterLexiconEntries(parameterDrafts) : (promptLexicons?.parameters ?? []),
  categories: isCategoryWorkspace ? normalizeImageLexiconEntries(categoryDrafts) : (promptLexicons?.categories ?? []),
  tags: isTagWorkspace ? normalizeTagImageLexiconEntries(tagImageDrafts) : (promptLexicons?.tags ?? []),
};

// normalize：仅 null 可 seed，空数组保持清空。
if (!promptLexicons) {
  return createDefaultPromptLexiconSettings(seedTagLabels);
}
return {
  parameters: normalizeParameterLexiconEntries(promptLexicons.parameters ?? []),
  categories: normalizeImageLexiconEntries(promptLexicons.categories ?? []),
  tags: normalizeImageLexiconEntries(promptLexicons.tags ?? [], { kind: "tag" }),
};
```
**违规特征**：`savePromptLexicons({ parameters: localDrafts, categories: staleMountDrafts, tags: staleMountDrafts })`；或对已清空的词库再 `mergeMissingParameterDefaults` / 启动全量 `syncPromptLexiconsFromLibrary` 把默认词条灌回磁盘；清空标签后 `tagOrder` 仍保留旧标签导致重启“又回来了”。

### R9: AI 分类必须区分稳定检索维度与视觉属性
**断言**：图片 / 提示词分类分析只允许输出对素材检索有稳定意义的内容类型、人物题材、服饰造型、场景类型、场景细分、主题领域、风格流派、应用场景、文化语境和时代风格。`光线条件`、`色彩体系`、`技术手法`、`情绪氛围`（包括「柔光」「棚拍光」「红色主导」「暖色主导」「浅景深」「深景深」「浪漫唯美」）属于视觉属性，不得进入详情分类展示、AI 分类持久化或分类词库自动同步。

**场景真实性边界**：`专业影棚` 只有在画面出现无缝背景 / 背景板边界 / 摄影灯具 / 灯架 / 摄影台，或没有建筑连续性的明确棚内空间时才允许使用。幕布、帷幔、屏风、主题道具、古装造型、摆拍姿态、商业布光、样片感都不能单独证明是影棚；真实墙面、门窗、梁柱、地面、固定装饰、家具陈设、连续透视、庭院、园林、街巷或古建筑应按真实场景归类。`棚拍光`只表示光源性质，不能推出`专业影棚`。

**人像边界**：`肖像摄影` 仅在人物面部 / 身份肖像本身是画面主旨、人物被作为被摄者突出呈现时使用。人物只是古装、仪式、故事或真实场景中的角色，且画面强调空间、道具和叙事时，不得仅凭出现人脸判为`肖像摄影`。

**实现要求**：模型 system/user 提示词必须同时包含上述边界；AI 结果进入 taxonomy 前必须再次过滤被禁止的视觉属性；详情页展示旧数据时也必须过滤这些属性，避免历史误分类继续出现。新增或修改分类边界必须有 Vitest 回归测试。

**违规特征**：仅因柔和光线、红色主色、浅景深、浪漫气氛或有一块幕布就返回对应分类；分类结果仍展示或保存上述视觉属性；模型提示词没有要求区分“棚拍光”和“专业影棚”；只修改 UI 文案而未过滤 AI 结果和旧数据。

### R10: 分类浏览必须消费 `genreIds`，标签分组必须按实体语义归类
**断言**：详情页已经保存的多分类结果必须完整进入分类浏览的菜单计数、筛选命中和提示词组展示；分类浏览不得只读取 `category` 或 `categoryId` 主分类而忽略 `genreIds`。标签词库必须优先按具体实体语义分组，环境物（如「芦苇」「太阳」）归入空间环境，动物实体（如「马匹」）归入动物，道具/附属器物（如「牵马绳」）归入道具与配饰；不得把这些词落入「其他标签」兜底组。
**示例**：
```ts
const categoryIds = [item.categoryId, ...(item.genreIds ?? [])].filter(Boolean);
```
**违规特征**：详情页显示「数字插画 / 奇幻插画 / 历史文化 / 户外自然」等附加分类，但分类库菜单只显示主分类「黄昏」；标签浏览中「芦苇」「太阳」「马匹」「牵马绳」进入「其他标签」；新增标签分组规则没有对应 Vitest 反例测试。
